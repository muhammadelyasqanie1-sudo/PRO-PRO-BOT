# ربات تلگرام – نسخهٔ حرفه‌ای

ربات عمومی با پنل مدیریت، ذخیره‌سازی SQLite، دو زبان (English / دری)، آمادهٔ اجرا روی Railway.

## امکانات

**شماره و OTP**
- ادمین می‌تواند شماره‌ها را دستی اضافه کند: `Service | Country | +Number`.
- مالک می‌تواند از پنل ربات API Key سازگار با Augestel را اضافه کند؛ ربات پس از ثبت، صفحات موجودی `/numbers` را می‌خواند و شماره‌های جدید را به‌طور خودکار وارد موجودی کاربران می‌کند.
- شماره‌های واردشده از API به‌صورت `All Services` ذخیره می‌شوند؛ کاربران ابتدا سرویس و سپس کشور را انتخاب می‌کنند. هنگام اختصاص شماره، سرویس انتخاب‌شده روی آن ثبت می‌شود و هر شماره فقط به یک کاربر اختصاص می‌یابد.
- ربات تمام صفحات را با صفحه‌بندی ارائه‌دهنده می‌خواند (حداکثر ۵۰۰ صفحه در هر همگام‌سازی)، شماره‌های تکراری را رد می‌کند و اگر ارائه‌دهنده اطلاعات صفحه‌بندی ندهد، تا صفحهٔ کوتاه‌تر از ۱۰۰ رکورد ادامه می‌دهد.
- در صورت تنظیم کلید API آگستِل، ربات پیامک‌های API را هر ۳۰ ثانیه بررسی می‌کند و OTP شمارهٔ اختصاص‌یافته را به همان کاربر می‌فرستد.
- قالب پاسخ API ممکن است با توجه به حساب/نسخهٔ پنل متفاوت باشد؛ اگر لاگ polling خطا داد باید مسیر و ساختار واقعی پاسخ مطابق مستندات حساب تنظیم شود.

**امتیاز و دعوت دوستان**
- هر کاربر جدید که از لینک دعوت شخص دیگری وارد شود، برای دعوت‌کننده ۱۰ بای‌کوین ایجاد می‌کند و شمارندهٔ دعوت‌ها یک واحد افزایش می‌یابد؛ برای یک حساب فقط یک بار.
- موجودی امتیاز، تاریخچه تغییرات و انتقال اتمیک امتیاز بین کاربران.
- مالک ربات یک‌بار ۱۰۰۰ امتیاز اولیه دریافت می‌کند؛ این امتیازها فعلاً مجازی‌اند و قابلیت برداشت پولی ندارند.
- مالک می‌تواند از پنل امتیاز کاربران را اضافه یا کم کند.

**مدیریت API**
- مالک از پنل API Key را اضافه، حذف یا فعال/غیرفعال می‌کند.
- پس از افزودن کلید، ربات بلافاصله تلاش می‌کند موجودی شماره‌ها را از API وارد کند؛ اگر همگام‌سازی ناموفق بود، کلید ذخیره می‌ماند و می‌توان از Provider Review دوباره همگام‌سازی کرد.
- کلیدها در پنل کامل نمایش داده نمی‌شوند؛ برای دریافت پیامک، ربات کلیدهای فعال را به‌ترتیب امتحان می‌کند.
- اگر کلیدهای مدیریت‌شده‌ای وجود نداشته باشد، متغیر AUGESTEL_API_KEY در Railway به‌عنوان جایگزین استفاده می‌شود.

**کاربران**
- انتخاب زبان، پروفایل، لینک دعوت اختصاصی و شمارش دعوت‌ها
- مشاهده موجودی امتیاز و ارسال امتیاز به کاربر دیگری که قبلاً ربات را شروع کرده است
- دکمه‌های پشتیبانی و کانال رسمی (لینک‌ها از پنل مدیریت تنظیم می‌شوند)

**پنل مدیریت** (`/admin` یا دکمهٔ «پنل مدیریت»)
- آمار: کل کاربران، فعال‌ها، مسدودشده‌ها، عضوهای امروز و ۷ روز اخیر، تعداد دعوت‌ها
- ارسال همگانی: هر نوع پیام (متن، عکس، ویدیو، فایل)، با تأیید قبل از ارسال و گزارش نهایی
- مسدود / آزاد کردن کاربر و دیدن اطلاعات کاربر
- عضویت اجباری در کانال‌ها (افزودن و حذف از داخل ربات)
- مدیریت ادمین‌ها (فقط مالک)
- مدیریت چند API Key و امتیازها (فقط مالک)
- حالت تعمیر (کاربران عادی پیام «در حال بروزرسانی» می‌بینند)
- تنظیم لینک پشتیبانی و کانال رسمی

## اجرا روی Railway

1. کد را در GitHub بگذارید و در Railway یک پروژه از روی آن بسازید.
2. در **Variables** این‌ها را بگذارید:
   - `BOT_TOKEN` : توکن از BotFather
   - `OWNER_ID` : آی‌دی عددی تلگرام شما (از ربات @userinfobot)
   - `DB_PATH` : `/data/bot.db`
   - `AUGESTEL_API_BASE` : `https://augestel.com/api/v1/iprn`
   - `AUGESTEL_API_KEY` : API key from your Augestel account (keep private)
   - `AUGESTEL_MESSAGES_PATH` : `/messages` unless your provider documentation specifies a different path
3. یک **Volume** بسازید و روی مسیر `/data` وصل کنید. بدون Volume با هر دیپلوی کاربران پاک می‌شوند.
4. `Procfile` سرویس را به‌صورت `web` اجرا می‌کند؛ ربات تلگرام و سرور Mini App در یک پردازش و با یک پایگاه داده کار می‌کنند. Railway متغیر `PORT` را برای سرور وب فراهم می‌کند.

## اجرا روی کامپیوتر

```bash
pip install -r requirements.txt
cp .env.example .env     # توکن و آی‌دی را در آن بنویسید
python -m bot
```

## عضویت اجباری

ربات باید در کانال **ادمین** باشد تا بتواند عضویت را بررسی کند. اگر ادمین نباشد، بررسی آن کانال رد می‌شود (تا کاربران قفل نشوند) و در لاگ هشدار می‌آید.

## ساختار

```
bot/
  app.py          ساخت برنامه و ثبت هندلرها
  guards.py       ثبت کاربر، مسدودی، حالت تعمیر، عضویت اجباری (قبل از همهٔ هندلرها)
  db.py           SQLite
  i18n.py         متن‌ها (برای زبان جدید یک دیکشنری اضافه کنید)
  handlers/       user.py ، admin.py ، router.py
tests/test_db.py  تست پایگاه‌داده
```

## نکتهٔ رابط کاربری
تلگرام برای دکمه‌های معمولی ربات رنگ سفارشی واقعی ارائه نمی‌کند؛ برای ظاهر بهتر از ایموجی، متن‌های واضح و چیدمان منظم استفاده شده است.

## نکتهٔ امنیتی

توکن را هرگز در کد یا GitHub ننویسید. اگر جایی فاش شده، در BotFather با `/revoke` توکن جدید بگیرید.

### پنل مدیریت دوزبانه / Bilingual admin panel

- دکمه‌های اصلی پنل به انگلیسی و دری نمایش داده می‌شوند؛ شامل آمار، پیام همگانی، کاربران، مسدودسازی، عضویت اجباری، مدیریت شماره‌ها، سرویس‌ها، کشورها، API، امتیازها و تنظیمات OTP.
- از بخش **Countries / کشورها** نام کشور سفارشی اضافه کنید؛ کشورهای افزوده‌شده در جریان افزودن شماره نیز نمایش داده می‌شوند.
- The main admin keyboard is bilingual (English / Dari). Custom countries can be added from **Countries / کشورها** and appear in the Add Number flow.
- تغییرات GitHub به‌تنهایی تضمین نمی‌کند Railway فوراً Deploy کند؛ وضعیت اجرای واقعی هنوز تأیید نشده است.


## مینی‌اپ تلگرام / Telegram Mini App

- رابط وب دوزبانه (English / دری) با طراحی واکنش‌گرا، کیف پول Buy Coin، فهرست سرویس‌ها و کشورها، موجودی واقعی پایگاه داده و نشست‌های شماره/OTP.
- مینی‌اپ از همان موجودی و SQLite ربات استفاده می‌کند؛ هر شماره فقط پس از اختصاص اتمیک از وضعیت «موجود» خارج می‌شود.
- درخواست‌های API بدون اعتبارسنجی امضای `Telegram.WebApp.initData` پذیرفته نمی‌شوند؛ نشست‌های منقضی یا دستکاری‌شده رد می‌شوند.
- وضعیت عضویت اجباری، مسدودی و حالت تعمیر نیز در API بررسی می‌شود.
- `GET /health` برای بررسی سلامت وب‌سرور؛ `GET /api/me`, `GET /api/catalog`, `GET /api/sessions` و `POST /api/number` برای Mini App.
- در Railway برای سرویس دامنهٔ عمومی HTTPS فعال کنید و متغیر `MINI_APP_URL` را برابر همان آدرس قرار دهید، مانند `https://your-service.up.railway.app`. سپس ربات را باز کرده و `/app` را بفرستید یا از دکمهٔ Mini App در منوی تلگرام استفاده کنید.
- `MINI_APP_URL` باید HTTPS باشد؛ در غیر این صورت تلگرام Web App را باز نمی‌کند.
- OTP فقط زمانی در مینی‌اپ ظاهر می‌شود که API ارائه‌دهنده پیامک واقعی را تحویل دهد و پیام به شمارهٔ اختصاص‌یافته مربوط باشد. مینی‌اپ خودش OTP تولید نمی‌کند.
- پنل Mini App برای ادمین‌های مجاز آمار کاربران، موجودی، صف بررسی ارائه‌دهنده، افزودن شماره به موجودی و فعال/غیرفعال کردن سرویس‌ها را فراهم می‌کند؛ API این عملیات را در سمت سرور نیز مجدداً مجازسنجی می‌کند.
- مسیرهای ادمین: `GET /api/admin/overview`، `POST /api/admin/number` و `POST /api/admin/service`.
- Buy Coin در حال حاضر امتیاز داخلی ربات است، نه پول نقد یا موجودی قابل برداشت.

### راه‌اندازی در Railway

1. در بخش **Settings → Networking** برای سرویس دامنهٔ عمومی ایجاد کنید.
2. در **Variables**، `MINI_APP_URL=https://...` را با دامنهٔ HTTPS همان سرویس تنظیم کنید.
3. یک Volume به مسیر `/data` وصل کنید و `DB_PATH=/data/bot.db` بگذارید تا کاربران، شماره‌ها و بای‌کوین با دیپلوی پاک نشوند.
4. `BOT_TOKEN` و `OWNER_ID` باید معتبر باشند. برای دریافت OTP از ارائه‌دهنده، کلید معتبر `AUGESTEL_API_KEY` یا کلید فعال اضافه‌شده از پنل ادمین نیز لازم است.
5. GitHub Actions آزمون‌های پایگاه داده، اعتبارسنجی Mini App و بررسی نحوی Python را اجرا می‌کند؛ اجرای موفق CI به‌تنهایی تأییدکنندهٔ اعتبار API یا دسترسی Railway نیست.
